1.0 General Goals

Build a small set of browser-based party games for a remote team to play together - should have no installs, no accounts, quick to join. Each game should feel familiar (inspired by games like Gartic Phone/scatterbrain) but include a twist (If taken from pre-existing game) so it isn't a direct copy.

2.0 Current System

The client's remote team currently plays existing online party games (e.g. Scattergories, Codenames). These work, but the client wants something original and tailored to their team, rather than relying on third-party sites.

3.0 Proposed System


3.1 Overview


A website holding multiple browser based games that can be played with a team.

3.2 Functional Requirements
Users can browse games. Player can create a room and receive a shareable code. Player/s can join a room using that code. The host can start the game once enough players have joined. Player/s can play a game. Player/s can see results after game completion.

3.3 Nonfunctional Requirements

3.3.1 User Interface and Human Factors

Each user/player that utilises the website should not be regarded with any skill. It should be inconsequential to their navigation and use of the system. The only user that requires sepcial treatment are complete beginners to computers, wherein failsafes, such as a short guide on how to play, can be utilised to prevent them from interacting in unitended ways.

3.3.2 Documentation

Documentation to be held includes; Design, Planning, README, How to use, File structure, Sprint related documentation.

3.3.3 Hardware Consideration

Hardware should be inconsequential to the system. Nothing specialized. As the system itself should be usable within any browser it should be stressed that lower end systems are able to view pages with throttling the users hardware. Additionally desktop support should be provided over alternative hardwares.

3.3.4 Performance Characteristics

There are no constraints on throughput for the system. As all data passed between server and user should be small in size due, not due to constraint, but due to the nature of the games being created. There will be constraints for the speed of delivery for the server dependent on real time games.

3.3.5 Error Handling and Extreme Conditions

Errors should be handled gracefully with a page dedicated to displaying error

3.3.6 System Interfacing

The system has no dependency on external systems for core functionality. All input (prompts, drawings, guesses) originates from players within the same room, and all output is delivered back to players within that room via the server. No external APIs are required for the MVP. If an AI-generated modifier or caption is added later, this would introduce a single outbound dependency on a third-party API, but this is not required for base functionality that we've got planned.

3.3.7 Quality Issues

The system should recover gracefully from individual player disconnects without disrupting the game for remaining players. A full server crash is not expected to preserve game state, given sessions are ephemeral by design. If the session itself is reset then simply disconnect players and boot to either an error, or a connect to lobby.

3.3.8 System Modifications

The system is expected to expand over time to support additional games beyond the initial MVP, additional modifiers within existing games, and potentially a scoring/leaderboard system if the specific game permits it. We'll endevour to use standardised assets to reduce workload, such as a standard lobby, rather than specialised lobbies for each game.

3.3.9 Physical Environment

Not applicable in a traditional sense, as the system is software-only and runs entirely in a standard web browser.

3.3.10 Security Issues

Given that the system does not store persistent data at all or require accounts, security requirements are minimal. Room codes act as the only access control available, and rooms should expire or become inaccessible after a period of inactivity to prevent stale rooms being rejoined.

3.3.11 Resource Issues

No backups are required, as all game data (prompts, drawings and guesses) is session-based and intentionally not persisted beyond the life of a lobby. The development team is responsible for installation, deployment, and maintenance of the server for the duration of the project. Perhaps extended to a few months after for maintanence on the deployed product. .

3.5 System Model

3.5.1 Scenarios

Browsing & Setup

  • As a user, I want to browse the available games, so that I can choose a game that I would like to play.
  • As a user, I want to view a brief description of each game, so that I can understand its basic rules and recommended player count before choosing it.
  • As a user, I want to select Sketch Recall from the game library, so that I can start setting up a game session.
  • As a user, I want to create a private game room, so that I can invite my teammates to play together.
  • As a user, I want to join a game room using a room code or invite link, so that I can quickly enter the same session as my teammates.
  • As a user, I want to enter a temporary nickname without creating an account, so that I can start playing quickly.

Lobby

  • As a player, I want to see who has joined the lobby and whether they are ready, so that I know when the group is ready to start.
  • As a player, I want to mark myself as ready or not ready, so that the host and other players know whether I am prepared to begin.
  • As a host, I want to select the game mode before starting the game, so that the group can choose between cooperative and competitive gameplay.
  • As a host, I want to start the game once enough players are ready, so that everyone can begin the game together.

Gameplay — Drawing Phase

  • As a player, I want to read a short explanation of the game rules before the game begins, so that I understand what I need to do.
  • As a player, I want to receive the same sequence of words as the other players, so that everyone plays under the same conditions.
  • As a player, I want the current grid cell to be clearly highlighted, so that I know where to draw each word.
  • As a player, I want basic drawing tools such as a pencil, eraser, and clear-cell function, so that I can quickly create and correct my sketches.
  • As a player, I want to see a countdown timer during the drawing phase, so that I know how much time I have left before the next word appears.
  • As a player, I want my drawing board to remain private during the drawing phase, so that other players cannot use my drawings as hints.
