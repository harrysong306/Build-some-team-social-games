Project Design Document (Draft)
1. Project Overview
Working Project Name
Multiplayer Social Game Platform
Concept
A browser-based multiplayer game platform consisting of multiple small multiplayer games built on top of a shared framework.
Instead of creating three completely separate games, the project will develop:
•	a reusable multiplayer infrastructure, 
•	shared assets, 
•	shared map systems, 
•	shared player systems, 
and then implement different game modes using the same foundation.
The three planned games are:
1.	Hidden — Social deduction / psychological strategy 
2.	The Lost Artifact — Deduction / information management 
3.	Crew — Cooperative task management 
The overall design philosophy:
Simple mechanics, meaningful decisions, and strong player interaction.
The project avoids unnecessary complexity such as:
•	advanced physics, 
•	real-time combat, 
•	complex animations, 
•	AI opponents, 
•	large open worlds. 
Instead, the focus is on:
•	multiplayer networking, 
•	game-state management, 
•	interactive web development, 
•	reusable software architecture.

6. Game Mode 1: Hidden
Genre
Social deduction.
Core Question
"Can you predict where other players will hide?"
 
Gameplay
Phase 1: Preparation
One player becomes:
The Seeker
Others become:
Hiders
Hiders choose hiding locations.
Example:
Alice → Closet

Bob → Bed

Charlie → Storage Box
 
Phase 2: Lock-In
Players cannot change their hiding spots.
 
Phase 3: Search
The seeker has limited searches.
Example:
Possible locations:
20
Available searches:
5
The seeker must decide where to search.
 
Phase 4: Reveal
If the seeker finds players:
They are eliminated.
If not:
The round continues.
 
Main Mechanic
Shared Risk
Example:
Closet capacity:
3 players.
Three players hide together.
Risk:
•	If safe → three survive. 
•	If discovered → all eliminated. 
 
Technical Requirements
Server stores:
{
playerID,
hidingLocation,
role
}
 
7. Game Mode 2: The Lost Artifact
Genre
Deduction and information management.
Core Question
"How long should you wait before taking the risk?"
 
Concept
A treasure is hidden somewhere on the map.
Players search locations over multiple rounds.
The goal:
Find the treasure before another player does.
 
Setup Example
Map:
20 locations.
Objects:
•	Bedroom 
•	Library 
•	Kitchen 
•	Basement 
•	Garden 
Hidden:
•	1 treasure 
•	2 clues 
 
Search Results
A player searches a location.
Possible outcomes:
1. Treasure
Player wins.
 
2. Empty
Player gains no information.
 
3. Clue
Only that player receives the clue.
Other players do not know.
 
Example
Alice searches:
Library
Everyone sees:
Alice searched Library
Only Alice receives:
Treasure is not outside.
 
Information System
Players accumulate knowledge.
Example:
Round 1:
Possible locations:
20
Round 3:
Possible locations:
5
Round 5:
Possible locations:
2
 
Strategic Decisions
Players choose:
Search immediately
Risk:
Someone else wins.
 
Wait and gather information
Risk:
Another player discovers the treasure first.
 
Technical Requirements
Server stores:
{
 treasureLocation:"basement",

 clues:[
 {
 location:"library",
 message:"Treasure is not outside"
 }
 ],

 searchedLocations:[]
}
 
8. Game Mode 3: Crew
Genre
Cooperative multiplayer strategy.
Core Question
"Can your team coordinate and specialise effectively?"
 
Concept
Players work together to maintain a system.
Theme examples:
•	Spaceship 
•	Haunted mansion 
•	Research station 
•	Factory 
The theme changes, but the mechanics remain the same.
 
Gameplay
The team receives tasks.
Example:
Spaceship:
Engine damaged

Oxygen system failing

Communication offline
Players assign themselves tasks.
 
Skills
Players start equally.
Example:
Engineering: 1

Cleaning: 1

Electronics: 1

Medical: 1
 
Upgrade System
After each round:
Players improve skills.
Possible strategies:
Specialisation
Example:
One player becomes the engineer.
Advantages:
Very efficient.
Disadvantages:
Team depends on one person.
 
Balanced Skills
Everyone learns everything.
Advantages:
Flexible.
Disadvantages:
Nobody becomes excellent.
 
Task Resolution
Example:
Task:
Repair Engine
Requirement:
Engineering Level 3
Player:
Engineering Level 1
Result:
Possible failure.
 
Technical Requirements
Server stores:
{
tasks:[

{
name:"Repair Engine",

skill:"engineering",

difficulty:3

}

],

players:[

{
skills:{
engineering:2
}

}

]
}

11. Final Project Vision
The final product is not simply three games.
It is:
A reusable browser-based multiplayer game framework capable of supporting different social and strategic game experiences.
The three games demonstrate different multiplayer interactions:
Game	Main Experience
Hidden	Bluffing and psychology
Lost Artifact	Deduction and information
Crew	Cooperation and planning
Together, they showcase:
•	frontend development, 
•	backend development, 
•	WebSocket networking, 
•	multiplayer architecture, 
•	reusable software design, 
•	game-state management. 
 
Final Design Philosophy
Simple systems create complex decisions.
